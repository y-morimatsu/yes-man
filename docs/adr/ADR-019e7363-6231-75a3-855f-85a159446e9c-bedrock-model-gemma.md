# Bedrock モデルを試行錯誤の末 Google Gemma 3 12B IT に決める

- **ADR ID**: `019e7363-6231-75a3-855f-85a159446e9c` (UUID v7)
- **slug**: `bedrock-model-gemma`
- **日付**: 2026-05-27
- **ステータス**: Accepted
- **関連コミット**: `62a9afe`, `ffc569e`, `bb03eb5`, `7bfbb5b`
- **関連 ADR**: [Bedrock RPM 制約への緩和策一式を入れる](ADR-019e7363-6619-7e5d-9572-bc3ea837ed5c-bedrock-rpm-mitigations.md)

## コンテキスト

新規アカウントの Bedrock は Claude Haiku 4.5 の RPM quota が 50 と低く、SSE のスループットがボトルネックになった。Sonnet は Marketplace subscription が必要等、モデル選定が二転三転した。

## 決定

JP inference profile の Claude Haiku → Sonnet → Haiku と試した末、RPM quota が 1000 (20 倍) の Google Gemma 3 12B IT に切り替える。`config.py` の default は Claude Haiku のまま、デプロイ時に Gemma 3 で上書きする。

## 結果 (トレードオフ)

- RPM 制約が緩和され SSE のスループットを確保できた。
- モデル差し替えが env だけで済む設計 ([llm-provider-protocol]) が効いた。
- プロンプトはモデル非依存に保つ必要がある。
