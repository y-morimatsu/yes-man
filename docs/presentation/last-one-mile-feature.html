Last One Mile.

YES の その先へ、
行動まで、AI が運ぶ。

YesMan の決定 (Decision) は今、スワイプで「閉じる」。

でも本当の終わりは、実際に観た / 買った / 食べた その瞬間にある。

本資料は、意思決定 後の深堀り質問 と 外部サービスへの deep-link 実行 を YesMan に追加する提案 — 通称 Last One Mile。

01 — The Gap

YES、その先で止まっている。

今の YesMan は「決まった」で完了する。でも、人はそこから「動く」必要がある。

— TODAY

現状: 決めて、終わり。

合議 → 提案 → Yes スワイプ。
画面には「決まったこと」 が残り、ユーザーは 自分でアプリを開き直す。

  • · 「今夜映画」 → Prime Video 開く → タイトル探す → 再生
  • · 「コーヒー切れた」 → Amazon 開く → 検索 → カート → 注文
  • · 「お腹空いた、何か食べたい」 → 出前館 開く → 店探す → ...

→ 判断は委任できたが、実行は自分でやる。

— TOMORROW

本来: YES の先、即実行へ。

合議 → 提案 → Yes → AI が深堀り → 外部サービスを直接開く。

  • ▸ 「今夜映画」 → 「ジャンルは?」 → Prime Video が起動・自動再生
  • ▸ 「コーヒー切れた」 → 「同じ豆?」 → Amazon の Buy Now ページに直行
  • ▸ 「お腹空いた」 → 「気分は?」 → 出前館の絞り込み済リストへ

→ 判断疲労 だけでなく 実行疲労 まで、肩代わり。

① 既存

合議 + スワイプ

3 persona の合議が断定調の提案を出力。右スワイプで Yes 採択。
→ ここまでは v0.4 で完成済

② 新規

深堀り質問の自動生成

提案の カテゴリ (映像 / 購入 / 飲食 / 音楽 …) に応じて、AI が 必要最小限 の絞り込み質問を 1〜3 問生成。
すべて Yes/No スワイプで答えられる形式。

③ 新規

Deep link 実行

絞り込み結果を URL クエリ / Universal Link に組み立てて、外部アプリを直接起動。
ユーザーは「実行に至る道のり」を一切歩かない。

04 — Drill-down Design

深堀りの設計指針。

「もう一度判断疲労にする」 のでは本末転倒。短く・断定的に・スワイプで。

① 量

1〜3 問まで

4 問以上は判断疲労を再生産する。LLM 側で「最重要 N 軸」 を選別。

② 形式

Yes/No スワイプ統一

本編 UI と完全に揃える。自由入力 / 多肢選択は 使わない。

③ 内容

嗜好 + 履歴を活用

過去 30 日の preference profile + 採択履歴で 多くの軸は既に推定済。AI は埋まらない穴だけ聞く。

④ Skip

「お任せ」 が常に選べる

「全部 Yes」 ボタンで 1 タップ即実行。判断疲労ゼロモード。

⑤ 復元

履歴に質問+回答を残す

後で振り返れるよう、決定詳細画面に 深堀りスレッド を保存。

⑥ Safety

沈黙 4 カテゴリは drill-down も発動しない

宗教 / 選挙 / 暴力 / 卑猥 は提案自体を生成しないので drill-down も自動的にスキップ。

⑦ 失敗時

Deep link 不発でも閉じない

アプリ未インストール / Universal Link 不通の時は Web fallback +「クリップボードにコピー」。

⑧ 一貫性

YesMan の世界観を保つ

外部サービスを開いた後も「YesMan で決めた」 体験。
Yes 採択履歴 / 委任度スコアに反映。

05 — Architecture

3 層で追加できる。

既存の Decision pipeline に 後段 として接続。Strategy + DI で外部サービスは差替え可能。

📥 Decision (既存)
user_input → 合議 → proposal_text + persona_outputs → Yes/No スワイプ
→ Yes 時にイベント発火 (`decision.accepted`)
↓
🔎 Intent Classifier (新規)
proposal_text + user_input → action_category (entertainment / purchase / food / music / travel / none)
→ 軽量 LLM (1-shot) または rule-based。none なら drill-down スキップ。
↓
🎯 Drill-down Engine (新規)
action_category + preference_profile + decision context → 1〜3 questions (Yes/No)
→ LLM プロンプトに「最大 N 問 / 既知の嗜好を再質問しない」 制約を埋め込み。
↓
🔌 Action Provider Registry (新規)
action_category + answers → provider (PrimeVideoProvider / AmazonProvider / DemaecanProvider / ...) を選択
→ 各 provider は `build_deep_link(answers) -> URL` のみ実装する小さな I/F (Strategy)。
↓
🚀 Execute (新規)
Universal Link / アプリスキーム / Web URL を生成 → ブラウザに `window.location.href` で遷移
→ 失敗時は Web fallback. 履歴に execution_url を保存。

07 — Why it matters

"YES" の意味が、深くなる。

判断疲労を取り除いても、
実行疲労 が残っていた。
― 決めるのは AI、でもアプリを開くのは あなた。

Last One Mile は、その最後の摩擦を消す。
YES を押した瞬間に、世界が動く。

📈 ユーザー価値

「決定 → 実行」 の所要時間が 30 秒 → 3 秒。
判断疲労 + 実行疲労 = ゼロ。

💰 ビジネス価値

各サービスとの affiliate 連携 が自然な収益源に。
Amazon associates / 出前館 partner program 経由。

🪞 ブランド価値

「決めて終わり」 ではなく 「決めて動く」 AI へ。
"Yes" の一語が現実を変える、唯一のサービス。

08 — Roadmap

段階的に、繋いでいく。

MVP は 3 サービスから。後は connector を足すだけ。

PHASE 1 — 0〜3 ヶ月

MVP: 3 connector

  • Amazon Prime Video (Universal Link)
  • Amazon (Cart API)
  • 出前館 (検索 URL + 絞り込み)
  • Drill-down engine v1 (max 2 問)
  • Intent classifier (entertainment / purchase / food / none)
  • 履歴に execution_url / drill-down 回答 を保存
PHASE 2 — 3〜9 ヶ月

Connector 拡張 + 体験強化

  • Uber Eats / Netflix / Spotify / Apple Music
  • 「お任せ」 1-tap で drill-down skip
  • Drill-down 履歴 → preference profile への学習反映
  • Affiliate ID 管理 (per-connector の収益トラッキング)
  • Deep link 失敗時の Web fallback / コピー復元
PHASE 3 — 9 ヶ月〜

真の Agentic 実行

  • 注文 / 決済まで YesMan 内で完結 (OAuth + 各サービス API)
  • 「Yes 1 回で、配達まで完了」 体験
  • Connector marketplace (3rd-party 開発者が追加可能)
  • カレンダー / リマインダー / IoT (スマートスピーカー)
  • API 公開: 他サービスが YesMan に「決定の委譲」 を依頼

Phase 1 の 3 connector + drill-down v1 は、 既存 codebase に約 800 行 の追加で実現可能 (Strategy + DI 利用)。
