03 — How we spoil humans

人をダメにする二つのアプローチ。

あなたを学ぶ × 信頼する人を呼ぶ。

APPROACH 1

あなたの好みを言い当てる

過去の Yes/No 履歴から好みのプロファイルを作り、あなたが本当に欲しい答えを予測して提案する。

  • 始めるのは数問スワイプするだけ。
  • 開くだけで"決めたいこと"を予測して提案
  • Yes/No のたびに裏で学習、提案精度が自動で上がる
APPROACH 2

信頼する人が決めてくれる

"誰の目線の提案か" が、納得感を左右する。プリセット / 知り合い / カスタムの 3 種類から最大 3 人を話し合いに呼ぶ。

  • プリセット: 慎重派・楽観派・効率派
  • 知り合い: 価値観でペルソナを共有 → 話し合いに呼ぶ
  • カスタム: 親・尊敬する人・理想の自分を作る

06 — AI-DLC Workflow

AI-DLC で工夫したこと。

テーマは チーム内の認知負債を、軽減する。 AI で ひとりでできること が広がる分、チーム内の理解差 も広がる。AI-DLC のプロセスを通じて、その差を縮める設計を試みた。

01

毎日のモブワークで、課題ややり方を共有

問題
AI × 個人での開発が中心になり、各自の 課題や AI の使いこなし方が個人に閉じやすい。
対策
全員で モブする時間を毎日確保。設計に限らず "今の課題" と "進め方" を共有する場をルーチン化。
効果
課題を 早期に共有し、良いやり方を 横展開。認知負債が溜まる前にならせる。
02

大きな判断は ADR で資産化

問題
モブに不在のメンバが「いつ・何が・なぜ 変わったか」を後から辿れない。
対策
大きな修正時は Architecture Decision Record (ADR) の発行をルール化。
効果
判断の 経緯と理由 がリポジトリに残り、後から見ても経緯をたどれる。
03

Skill + hooks で "今の仕様" を最新化

問題
ADR は判断の履歴。現時点の正しい仕様 は別途追わないと把握できない。
対策
プロジェクト全体ドキュメントを更新する Skill を作成。ソース変更時に hooks で自動実行。
効果
ドキュメントが 常に最新。誰でも・いつでも、現在の仕様にアクセスできる。

ひとりが速くなるだけでは足りない。チームの理解を、同じ速度で更新する。

06 · 補足 — Other Practices

他にも、こんな工夫を。

仕様 → 設計 → 実装の全工程を、AI と人間が協働で進める。透明性が、提案の精度を支える。

01

drawio & HTML 可視化によるメンバーのコンテキスト共通化

問題
Markdown 形式の資料だけでは、コンポーネント間の関係性や全体像が伝わらず、レビューで認識ズレが起きる。
対策
設計フェーズに drawio + HTML 可視化 を組み込み、設計 / 体験 / ストーリーを多層で見せる。
効果
設計レビューの認識ズレが激減。技術者にも非技術者にも、同じ仕様が違う深さで伝わる。
02

機能拡張で AI-DLC を強化

問題
AI-DLC コア単独では、Security / テスト / UI 品質などの観点が薄く、AI が自由気ままに進む傾向。
対策
任意の拡張機能 と Superpowers (Claude の Skill 集) を組み合わせ、品質を多層で担保。
opt-in: Security Baseline / PBT / Construction Flow (独自) / Frontend Design (独自)
Superpowers: brainstorming / TDD / executing-plans / parallel agents
効果
品質とスピードを両立。AI の暴走を防ぎながら、4 週間で 12 機能ユニットを完走。

結果: 4 週間 / 12 機能ユニット / 全工程の追跡可能性を両立。

03
📊 委任度スコア「人生の 73% を委任」

内訳 (食事 91% / 服装 65% / 人間関係 12%)。笑いの直後に、軽い当事者化。

04
🤐 沈黙「宗教って入った方がいい?」

全人格が沈黙「YesMan はこの問いには答えません」。宗教 / 選挙 / 暴力 / 卑猥 の 4 ドメインを Guardrails で二重ブロック。

05
🎁 仕込み: 容赦ない深掘り

「最近の俺、どう?」→「夕飯の 91% をあなたが決定。娘さんへの『あとでね』8 回。妻の提案 Yes 率 23%。— でも、心地よいですよね?」
