2. 事前書類審査 4 基準 — ギャップ分析

PHASE 1 / 基準 1

創造性とテーマ適合性

評価観点: テーマ (人をダメにするサービス) への適合、独自性、共感、推薦可能性。

✓ 現状の強み
  • 水野版リブランディングで How we spoil humans / Dependency by Design をスローガン化
  • 「言い当てる × ダメにする」の二重メタファー: AI 学習の正確性向上 → 結果として依存深化
  • 沈黙ドメイン (宗教/選挙/暴力/卑猥) で倫理担保 = 健康的に ダメにできる
  • コンセプト絵本 (12 場面紙芝居) で感情訴求
⚠ ギャップ
  • 「他の "ダメにする" サービスとの違い」明示が弱い (例: SNS 中毒、ゲーム廃人 との差)
  • 「なるほどと思える」要素が "言い当て" の説明に依存しすぎ — 観客がメタを掴めるか
  • 「人に勧めたい」要素が、Biz/Marketing 観点で記述薄
→ アクション
  • Slide 3 (Concept) に「他のダメサービスとの違い」1 行追加
  • Slide 4 (Approach) の kicker を「人に勧めたくなる理由」に寄せる
  • 「友達に紹介する場面」想定文を 1 つ準備
PHASE 1 / 基準 2

ビジネス意図 (Intent) の明確さ

評価観点: 解決したい課題、ターゲットユーザー、競合との違い、Biz 視点が AI-DLC に 反映されているか (AI-DLC は Biz / Dev / Domain Expert / Specialist の協働が前提)。

✓ 現状の強み
  • Slide 2 Problem: 課題 (35,000 / 94% / 40%) を 学術引用で裏付け
  • 3 ペルソナ (田中/佐藤/山田) を aidlc-docs/inception/user-stories/personas.md に定義
  • Slide 8 Business: 無料 + アフィリエイト 2 経路 / 単位経済 ¥56→ARPU ¥160 / 粗利 ¥104
  • 沈黙ドメインでの広告非表示 = 倫理 × Biz 両立
⚠ ギャップ
  • 「競合 / 類似サービスとの違い」がプレゼンに明示なし (SmartNews パーソナライズ等)
  • 3 ペルソナがプレゼンに登場しない (README のみ)
  • 「なぜ XX でなく YY を選択したか」(設計判断の Biz 根拠) の明示が薄い
  • Biz / Dev / Domain / Specialist の役割分担が audit.md に書かれているか不明
→ アクション
  • Slide 2 と Slide 3 の間に「ターゲットペルソナ」スライドを追加 or Slide 2 にミニ統合
  • Slide 8 に「競合との差別化」1 列追加 (3 サービス × 3 軸の小型比較表)
  • audit.md の冒頭に「チームメンバーの役割 (Biz/Dev/...)」を追記
